# 02 项目结构

## 1. 顶层布局

```
OpenCOOD/
├── opencood/                 # ★ 核心代码包（框架本体）
├── docs/                     # Sphinx 文档
│   ├── md_files/             #   官方教程（7 篇：config/data/annotation/installation/benchmark/logic_flow/contributor）
│   └── md_files_vga/         #   ★ 本文档目录
├── logreplay/                # OPV2V 日志回放工具（CARLA 重新仿真、增删传感器）
├── images/                   # README 用图
├── environment.yml           # conda 环境
├── requirements.txt          # pip 依赖
├── setup.py                  # 打包脚本（只做 find_packages + 读 requirements，不编译 CUDA）
└── README.md                 # 项目主页 / 基准结果表
```

`logreplay/` 是一个**独立子系统**（18 个 py 文件），用于把离线数据集 100% 回放到 CARLA 中重新采集传感器数据。它不参与训练/推理主链路，初学者可暂时忽略。

## 2. `opencood/` 核心包结构

```
opencood/
├── hypes_yaml/               # ★ 配置中心：23 个 yaml，一文件一实验
│   ├── yaml_utils.py         #   配置加载 + 派生量计算（grid_size / anchor W,H）
│   └── point_pillar_*.yaml
├── data_utils/               # ★ 数据层：读盘 → 坐标变换 → 体素化 → 标注编码
│   ├── datasets/             #   Dataset 类（3 种融合 + V2 + 可视化专用）
│   ├── pre_processor/        #   点云 → 体素 / BEV
│   ├── post_processor/       #   标注 → anchor target；输出 → 3D 框
│   └── augmentor/            #   数据增强（翻转、旋转、缩放）
├── models/                   # ★ 模型层：backbone + 融合 + 检测头
│   ├── sub_modules/          #   通用积木（VFE/Scatter/BEV backbone/压缩/GRU）
│   ├── fuse_modules/         #   融合算子的各种实现
│   └── *.py                  #   每个文件 = 一个可被 yaml 引用的模型
├── loss/                     # 损失函数（anchor-based 检测损失）
├── tools/                    # ★ 入口：train / inference / 多卡 / 训练辅助
├── utils/                    # 几何、IO、评估、可视化工具
├── visualization/            # 点云序列可视化脚本
├── pcdet_utils/              # OpenPCDet 抽出的 CUDA 算子（IoU3D-NMS、PointNet++、RoI pool）
└── version.py
```

## 4. 「配置 → 代码」映射表

这是全项目**最重要的跳转关系**：yaml 里写一个字符串，`importlib` 就去对应目录找同名文件、同类名（忽略大小写与下划线）。

| yaml 字段 | 到哪找代码 | 举例 |
|---|---|---|
| `fusion.core_method` | `data_utils/datasets/__init__.py` 的 `__all__` 字典 | `'IntermediateFusionDataset'` |
| `preprocess.core_method` | `data_utils/pre_processor/__init__.py` 的 `__all__` | `'SpVoxelPreprocessor'` |
| `postprocess.core_method` | `data_utils/post_processor/__init__.py` 的 `__all__` | `'VoxelPostprocessor'` |
| `model.core_method` | `opencood/models/<name>.py` 中的同名类 | `point_pillar_v2vnet` → `PointPillarV2VNet` |
| `loss.core_method` | `opencood/loss/<name>.py` 中的同名类 | `point_pillar_loss` → `PointPillarLoss` |
| `yaml_parser` | `hypes_yaml/yaml_utils.py` 中的同名函数 | `load_point_pillar_params` |

**反射规则**（`train_utils.py:116-135`）：

```python
model_filename = "opencood.models." + backbone_name      # 模块名 = yaml 字符串
model_lib = importlib.import_module(model_filename)
target_model_name = backbone_name.replace('_', '')       # 去掉下划线
for name, cls in model_lib.__dict__.items():
    if name.lower() == target_model_name.lower():        # 忽略大小写比对
        model = cls
```

因此命名必须满足：**yaml 值去掉下划线后 == 类名忽略大小写**。
- `point_pillar_v2vnet` → `pointpillarv2vnet` ↔ `PointPillarV2VNet` ✅
- `point_pillar_intermediate` → `pointpillarintermediate` ↔ `PointPillarIntermediate` ✅

> 注意 `point_pillar_intermediate_V2VAM` 的去下划线结果是 `pointpillarintermediateV2VAM`，与类名 `PointPillarintermediateV2VAM`（小写 i）忽略大小写后一致 ✅。这类命名不一致是历史遗留，改名前务必核对。

## 5. 已注册的配置清单（23 个 yaml）

| 融合范式 | PointPillar | VoxelNet | SECOND | PIXOR |
|---|---|---|---|---|
| **Early** | `point_pillar_early_fusion` | `voxelnet_early_fusion` | `second_early_fusion` | `pixor_early_fusion` |
| **Late** | `point_pillar_late_fusion` | `voxelnet_late_fusion` | `second_late_fusion` | `pixor_late_fusion` |
| **Intermediate** | `point_pillar_intermediate_fusion`（无融合，⚠️见下）<br>`point_pillar_fcooper`<br>`point_pillar_v2vnet`<br>`point_pillar_v2xvit`<br>`point_pillar_cobevt`<br>`point_pillar_where2comm`<br>`point_pillar_coalign`<br>`point_pillar_intermediate_V2VAM` | `voxelnet_intermediate_fusion` | `second_intermediate_fusion` | `pixor_intermediate_fusion` |

另有 `fpvrcnn_intermediate_fusion`、`ciassd_early_fusion`、`ciassd_intermediate_fusion`、`visualization.yaml`。

> 三个「名不副实」的配置，容易误判：
> 1. `point_pillar_intermediate_fusion.yaml` → 模型 `point_pillar_intermediate`，**无融合模块**；且它不回读 `record_len`，输出第 0 维是「车数」而非 batch，多车场景下会与损失维度不匹配（见 [05 §5.1](05_模型原理.md)）；
> 2. `ciassd_intermediate_fusion.yaml` → 模型 `voxel_net_intermediate` + 损失 `point_pillar_loss`，**不是 CIASSD**（CIASSD 只出现在 early fusion 配置中）；
> 3. `point_pillar_late_fusion.yaml` / `second_late_fusion.yaml` / `voxelnet_late_fusion.yaml` 的 LiDAR 范围是 **±70.4 m**（其余多为 ±140.8 m）。

> 另外注意**「yaml 文件名」与「模型文件名」不必同名**：`point_pillar_v2xvit.yaml` 指向的 `core_method` 是 `point_pillar_transformer`，对应文件是 `opencood/models/point_pillar_transformer.py`（类 `PointPillarTransformer`）。找 V2X-ViT 的代码时不要去找 `point_pillar_v2xvit.py`——它不存在。

## 6. 建议的代码阅读顺序

按「一条数据走完全程」的路径读，比按目录读高效得多：

```
① tools/train.py:36-203            # 看清训练循环只有 3 个调用：build_dataset / create_model / criterion
        ↓
② data_utils/datasets/__init__.py  # build_dataset 工厂，确认 fusion.core_method 的作用
        ↓
③ basedataset.py:60-263            # 场景库怎么建、idx 怎么映射到 (scenario, timestamp)
        ↓
④ intermediate_fusion_dataset.py:56-243   # ★ 核心：__getitem__ 全流程
        ↓
⑤ sp_voxel_preprocessor.py:59-82   # 点云 → 体素
        ↓
⑥ voxel_postprocessor.py:78-198    # GT → anchor target（正负样本分配）
        ↓
⑦ models/point_pillar_v2vnet.py:74-109     # backbone + fusion + head 的组装
        ↓
⑧ models/fuse_modules/v2v_fuse.py:51-150   # 融合算子内部
        ↓
⑨ loss/point_pillar_loss.py:84-146 # 损失
        ↓
⑩ tools/inference.py:103-202       # 推理与评估
```
