本文是「动手改」的操作手册：如何新增模型/数据集，以及框架中那些**没有写在文档里、但会让人调一整晚的隐式约束**。

## 1. 新增一个中间融合模型（最常见需求）

### 1.1 三步走

```
① 写模型文件  opencood/models/point_pillar_<yourmethod>.py
② 写配置     opencood/hypes_yaml/point_pillar_<yourmethod>.yaml
③ 训练       python opencood/tools/train.py --hypes_yaml <yaml>
```

**不需要修改任何框架代码**——`create_model` 通过 `importlib` 反射加载。

### 1.2 模型文件模板

```python
# opencood/models/point_pillar_mymethod.py
import torch.nn as nn

from opencood.models.sub_modules.pillar_vfe import PillarVFE
from opencood.models.sub_modules.point_pillar_scatter import PointPillarScatter
from opencood.models.sub_modules.base_bev_backbone import BaseBEVBackbone
from opencood.models.sub_modules.downsample_conv import DownsampleConv


class PointPillarMyMethod(nn.Module):          # ★ 类名 = yaml 值去下划线、忽略大小写
    def __init__(self, args):                  # ★ 只接收 args，即 yaml 的 model.args
        super().__init__()
        self.pillar_vfe = PillarVFE(args['pillar_vfe'],
                                    num_point_features=4,
                                    voxel_size=args['voxel_size'],
                                    point_cloud_range=args['lidar_range'])
        self.scatter = PointPillarScatter(args['point_pillar_scatter'])
        self.backbone = BaseBEVBackbone(args['base_bev_backbone'], 64)
        self.shrink_conv = DownsampleConv(args['shrink_header'])
        # ---- 你的融合模块 ----
        self.fusion_net = MyFusion(args['my_fusion'])
        # ---- 检测头：输入通道必须等于融合输出通道 ----
        self.cls_head = nn.Conv2d(256, args['anchor_number'], kernel_size=1)
        self.reg_head = nn.Conv2d(256, 7 * args['anchor_number'], kernel_size=1)

    def forward(self, data_dict):
        voxel_features = data_dict['processed_lidar']['voxel_features']
        voxel_coords   = data_dict['processed_lidar']['voxel_coords']
        voxel_num      = data_dict['processed_lidar']['voxel_num_points']
        record_len     = data_dict['record_len']              # ★ (B,) 逐样本车数

        batch_dict = {'voxel_features': voxel_features,
                      'voxel_coords': voxel_coords,
                      'voxel_num_points': voxel_num,
                      'record_len': record_len}
        batch_dict = self.pillar_vfe(batch_dict)      # (ΣM,64)
        batch_dict = self.scatter(batch_dict)         # (Σn,64,200,704)
        batch_dict = self.backbone(batch_dict)        # (Σn,384,100,352)
        feat = self.shrink_conv(batch_dict['spatial_features_2d'])   # (Σn,256,50,176)

        fused = self.fusion_net(feat, record_len)     # (B,256,50,176)

        return {'psm': self.cls_head(fused), 'rm': self.reg_head(fused)}
```

**必须遵守的三条契约**：

| 契约 | 违反后果 |
|---|---|
| `__init__(self, args)` 单参数 | `create_model` 直接调用 `model(backbone_config)`，TypeError |
| `forward(data_dict)` 返回含 `'psm'` 与 `'rm'` 的 dict | `criterion` 中 `output_dict['rm']` KeyError |
| `psm` 通道 = `anchor_number`，`rm` 通道 = `7×anchor_number`，空间分辨率 = anchor 网格 | `delta_to_boxes3d` 形状不匹配 |

### 1.3 yaml 模板

```yaml
name: point_pillar_mymethod
root_dir: 'opv2v_data_dumping/train'
validate_dir: 'opv2v_data_dumping/validate'
yaml_parser: "load_point_pillar_params"

train_params:
  batch_size: &batch_size 2
  epoches: 60
  eval_freq: 1
  save_freq: 1
  max_cav: &max_cav 5

fusion:
  core_method: 'IntermediateFusionDataset'
  args:
    proj_first: true

preprocess:
  core_method: 'SpVoxelPreprocessor'
  args:
    voxel_size: &voxel_size [0.4, 0.4, 4]
    max_points_per_voxel: 32
    max_voxel_train: 32000
    max_voxel_test: 70000
  cav_lidar_range: &cav_lidar [-140.8, -40, -3, 140.8, 40, 1]

postprocess:
  core_method: 'VoxelPostprocessor'
  anchor_args:
    cav_lidar_range: *cav_lidar
    l: 3.9
    w: 1.6
    h: 1.56
    r: [0, 90]
    feature_stride: 4            # ★ 必须等于 shrink_header 的总 stride
    num: &achor_num 2
  target_args: {pos_threshold: 0.6, neg_threshold: 0.45, score_threshold: 0.20}
  order: 'hwl'
  max_num: 100
  nms_thresh: 0.15

model:
  core_method: point_pillar_mymethod        # ★ = 文件名；类名去下划线后需匹配
  args:
    voxel_size: *voxel_size
    lidar_range: *cav_lidar
    anchor_number: *achor_num
    max_cav: *max_cav
    compression: 0
    backbone_fix: false
    pillar_vfe: {use_norm: true, with_distance: false, use_absolute_xyz: true, num_filters: [64]}
    point_pillar_scatter: {num_features: 64}
    base_bev_backbone:
      layer_nums: [3, 5, 8]
      layer_strides: [2, 2, 2]
      num_filters: [64, 128, 256]
      upsample_strides: [1, 2, 4]
      num_upsample_filter: [128, 128, 128]
    shrink_header:
      kernal_size: [3]
      stride: [2]              # ★ 与 feature_stride 联动
      padding: [1]
      dim: [256]
      input_dim: 384           # 128*3
    my_fusion: {...}

loss:
  core_method: point_pillar_loss
  args: {cls_weight: 1.0, reg: 2.0}

optimizer:
  core_method: Adam
  lr: 0.001
  args: {eps: 1e-10, weight_decay: 1e-4}

lr_scheduler:
  core_method: multistep
  gamma: 0.1
  step_size: [10, 15]
```

> 上面的范围是 `±40 m`（`ny=200`），因此 `shrink stride 2` + `feature_stride 4` 得到 `176×50`。若你沿用 V2X-ViT 的 `±38.4 m`（`ny=192`），结果会是 `176×48`——**两处 stride 都不用改，但 anchor 数会从 17600 变成 16896**，务必用 §5.1 的脚本核对。

## 2. 隐式约束清单（★ 最重要的一节）

这些是官方教程未覆盖、但违反了会报错或静默出错的约束。

| # | 约束 | 违反后果 | 如何自查 |
|---|---|---|---|
| 1 | `anchor 网格 = (W // feature_stride) × (H // feature_stride)`，且必须等于检测头输出分辨率 | `delta_to_boxes3d` 形状不匹配 | 打印 `anchors.view(-1,7).shape` 与 `rm.shape` |
| 2 | `feature_stride = 2 × shrink_header.stride`（那个 2 是 BEV backbone 自带的 /2 下采样），且两者都相对于该 yaml 自己的 BEV 尺寸 | 同上 | 见 [03 §3.2](03_配置系统.md) 对照表、[06 §10](06_端到端数据流.md) 速查表 |
| 3 | **ego 必须在 regroup 后的第 0 位** | V2X-ViT 的 STTF 只 warp `[:,1:]`、注意力取 `[0]`，顺序错则融合到错误车辆 | 依赖 `scenario_database` 顺序，勿手动打乱 |
| 4 | `voxel_coords` 列序是 `[car_idx, z, y, x]` | 自定义 VFE/scatter 时坐标错位、BEV 图旋转 90° | 对照 `PillarVFE.forward` 的 `f_center` |
| 5 | `pairwise_t_matrix` 在 `proj_first=True` 时全为 I | 误用会导致特征被二次 warp（几何错乱） | 检查 `intermediate_fusion_dataset.py:432-436` |
| 6 | 中间融合**不做数据增强** | yaml 里 `data_augment` 静默失效 | 全局 grep `self.augment` |
| 7 | 时延单位是「帧」，不是 ms | `time_delay` 作为先验编码会差 100 倍 | `basedataset.py:375` 的 `// 100` |
| 8 | 窗口注意力要求特征图 H/W 被 `window_size` 整除 | V2X-ViT（4/8/16）、CoBEVT（4）在 `H'=50` 时直接抛 rearrange 错误 | 用 ±38.4 m 使 `H'=48`，或改 `window_size` |
| 9 | `--model_dir` 会**覆盖** `--hypes_yaml` | 改了原 yaml 但不生效 | 直接改 `<model_dir>/config.yaml` |
| 10 | `compression` 在多数 yaml 中是**整数**（0 或压缩后通道数），而 Where2comm 用 `if args['compression']` 布尔判断；其 `multi_scale=True` 分支还**绕过压缩**（高分辨率通信） | 0/非 0 恰好等价，但「压缩在哪一层生效」与其它模型不同，跨模型比较带宽时易误判 | 参考对应模型的 yaml 与 forward 分支 |
| 11 | RSU 的 `cav_id` 为负数 | 若数据集中把所有 id 当正数，`infra` 标志恒 0 | `int(cav_id) < 0` |
| 12 | `max_cav` 与数据实际车数 | 超出部分的车**在索引阶段就被丢弃**，不是补零 | 观察是否打印 `too many cavs` |
| 13 | `--half` 与多卡训练互斥 | README 明确「cannot be set with multi-gpu training together」，但代码**没有断言**，同时开启会静默进入 AMP+DDP 分支，行为不可预期 | 检查启动命令里是否同时出现 `--half` 与 `torch.distributed.launch` |
| 14 | 训练期 GT 用 `cav_lidar_range` 裁剪，**测试期改用固定 `GT_RANGE`** | 小范围配置（如 Late 的 ±70.4）测试时 GT 保留到 ±140，评估范围与训练不一致 | `base_postprocessor.py:129-130` |
| 15 | `point_pillar_coalign` 用 `if 'compression' in args` 判断（键在即为真），而 yaml 写的是 `compression: 0` | 构造模型时 `NaiveCompressor(64, 0)` → `ZeroDivisionError`，CoAlign **完全无法启动** | 见 §5.6 |
| 16 | `pairwise_t_matrix` 按**全部 CAV**（含 70 m 外的）建立，而特征列表只含范围内的车 | 开 `proj_first=False` 时 `pairwise_t_matrix[b][:N,:N]` 与 `record_len` 错位 → 几何 warp 到错误的车，**静默出错** | 默认 `proj_first=True`（全 I）时被掩盖；开特征级对齐前必修 |
| 17 | V2VAM 的 `att` 列表定义在样本循环外 | batch>1：车数不同则 `RuntimeError`，车数相同则**跨样本污染**（yaml `batch_size: 4`） | 见 [05 §5.9](05_模型原理.md) |

## 3. 新增 backbone

若新 backbone 输出的通道数/分辨率不是 `(N, 384, H/2, W/2)`，需要同步调整：

1. `model.args.shrink_header.input_dim`（PointPillar 为 `384 = 128×3`）
2. `shrink_header.stride` 与 `postprocess.anchor_args.feature_stride`（二者必须匹配）
3. `cls_head` / `reg_head` 的输入通道（需等于 shrink 的 `dim[-1]`，PointPillar 通常为 `256`）
4. 若不用 PointPillar 的体素化，还要换 `preprocess.core_method` 与 `yaml_parser`（`load_voxel_params` / `load_second_params` / `load_bev_params`）

> 参考已有的第二种 backbone：`voxel_net.py` + `voxelnet_*.yaml`（`load_voxel_params`）、`second.py` + `second_*.yaml`（`load_second_params`）、`pixor.py` + `pixor_*.yaml`（`load_bev_params`）。
>
> 注意 `voxelnet_*` / `ciassd_*` / `fpvrcnn_*` 的 LiDAR 范围是 **±41.6 m**（`ny=208`、`voxel_size=[0.4,0.4,0.4]`），所以 `voxelnet_intermediate_fusion` 的 anchor 网格是 `352×104` 而不是 `176×50`，且体素在 z 向有 10 层（4 m / 0.4）。**换 backbone 时网格尺寸、层数、前后处理都会一起变**，不能照抄 PointPillar 的数值。

## 4. 新增数据集

若你的数据目录结构与 OPV2V 不同（`scenario/cav_id/timestamp.pcd`），有两条路径：

**路径 A（推荐，零侵入）**：把新数据集**转换成 OPV2V 目录格式**。需要满足：

```
<root>/
  <scenario_name>/
    <cav_id>/                     # cav_id 为数字字符串，RSU 用负数
      <5位数字时间戳>.pcd          # (N,4) x y z intensity
      <5位数字时间戳>.yaml         # 至少含 lidar_pose、vehicles、ego_speed
```

**路径 B（改代码）**：新增 `mydataset.py` 并在注册表登记：

```python
# opencood/data_utils/datasets/__init__.py
from ... import MyDataset
__all__ = {..., 'MyDataset': MyDataset}

# build_dataset 中的 assert 也要加白名单，否则直接 AssertionError
assert dataset_name in ['LateFusionDataset', ..., 'MyDataset']
```

⚠️ `build_dataset` 的 `assert` 是**硬白名单**，只加 `__all__` 而忘记改 `assert` 会在运行时失败。

## 5. 常见报错与定位

### 5.1 `RuntimeError: The size of tensor a (67584) must match the size of tensor b (16896)`

**成因**：`delta_to_boxes3d` 中 `deltas`（检测头输出解码出的框数）与 `anchors` 数量不一致，即约束 #1/#2 被违反。

**定位**（先算期望值，再看实际值）：

```python
aa = hypes['postprocess']['anchor_args']
W, H, fs, num = aa['W'], aa['H'], aa['feature_stride'], aa['num']
print('期望 anchor 数 =', (W // fs) * (H // fs) * num)      # 例：704//4 × 192//4 × 2 = 16896
print('rm 通道 =', rm.shape[1], '→ 实际框数 =', rm.shape[2] * rm.shape[3] * rm.shape[1] // 7)
print('anchors =', anchors.view(-1, 7).shape[0])
```

**比值判读**：

| `实际 / 期望` | 含义 | 修法 |
|---|---|---|
| 4 | 两个空间维各多 2 倍 → `shrink` 的 stride 少了 2 | 改 `shrink_header.stride` 或 `feature_stride` 之一 |
| 2 | 只有一个维度不匹配 → `ny`（LiDAR 范围）改过而 `feature_stride` 没跟着改 | 核对 `cav_lidar_range` 与 `feature_stride` |
| 1.0 | 数量对但顺序错（如 `hwl` 写成 `lhw`） | 检查 `postprocess.order` |

### 5.2 `KeyError: 'record_len'`

**成因**：模型 forward 读了 `record_len`，但用了 `EarlyFusionDataset`（不产出该键）。
**定位**：检查 yaml 的 `fusion.core_method` 与 `model.core_method` 是否匹配。

### 5.3 训练 loss 正常但推理 AP 极低

按概率排查：

1. `validate_dir` 仍指向验证集而非测试集（README 明确要求测试前修改）；
2. `torch.load` 加载了错误 epoch（`load_saved_model` 取**最大** epoch，而非最优）；
3. `--fusion_method` 与模型不匹配（如 V2X-ViT 必须用 `intermediate`）；
4. `global_sort_detections` 未与论文对齐（会虚高或虚低）。

### 5.4 spconv 版本问题

```python
# sp_voxel_preprocessor.py:22-28
try:    from spconv.utils import VoxelGeneratorV2   # spconv 1.x
except: from spconv.utils import Point2VoxelCPU3d   # spconv 2.x
```

两版接口不同（`generate()` vs `point_to_voxel()`，返回 dict vs tuple），代码已做兼容。但 **spconv 2.x 的 `coors` 是 `(z,y,x)` 顺序**，与 OpenPCDet 的部分实现不一致，自行写算子时需注意。

### 5.5 CUDA 扩展未编译

`pcdet_utils/` 下的 `iou3d_nms`、`pointnet2`、`roiaware_pool3d` 需要编译。**必须在仓库根目录执行**（两个 `setup.py` 里的源文件路径都是相对仓库根写的，`cd` 进去反而找不到）：

```bash
# 位于 OpenCOOD/ 根目录
python opencood/utils/setup.py build_ext --inplace        # box_overlaps.pyx（Cython）
python opencood/pcdet_utils/setup.py build_ext --inplace  # iou3d_nms / pointnet2 / roiaware_pool3d（CUDA）
```

> 根目录的 `setup.py` 只做打包（`find_packages` + 读 `requirements.txt`），**不编译任何 CUDA 扩展**，`pip install -e .` 不能替代上面两步。

**只有 FPV-RCNN / CIASSD 依赖它们**；PointPillar 系列不需要。

### 5.6 `ZeroDivisionError: integer division or modulo by zero`

**成因**：`point_pillar_coalign.yaml` 的 `model.args` 里有 `compression: 0`，而 `point_pillar_coalign.py:44` 判断的是

```python
if 'compression' in args:                    # 键存在 → 恒为 True，与值无关
    self.naive_compressor = NaiveCompressor(
        args['res_bev_backbone']['num_filters'][0], args['compression'])
```

`NaiveCompressor.__init__` 会算 `input_dim // compress_raito`，于是 `64 // 0` 直接抛异常。其它模型（V2VNet / V2X-ViT / CoBEVT / F-Cooper / V2VAM）都写成 `if args['compression'] > 0`，所以只有 CoAlign 中招。

**修法**（二选一）：

```python
# 方案 A：改代码
if args.get('compression', 0) and args['compression'] > 0:

# 方案 B：改 yaml —— 直接删掉 model.args.compression 这一行
```

## 6. 调试技巧

### 6.1 单样本可视化（跳过训练）

```python
import yaml, torch
from opencood.hypes_yaml import yaml_utils
from opencood.data_utils.datasets import build_dataset

hypes = yaml_utils.load_yaml('opencood/hypes_yaml/point_pillar_v2vnet.yaml')
ds = build_dataset(hypes, visualize=True, train=False)
sample = ds[0]
print(sample['ego']['cav_num'], sample['ego']['object_bbx_center'].shape)
print({k: v.shape if hasattr(v,'shape') else type(v)
       for k, v in sample['ego']['processed_lidar'].items()})
```

`visualize=True` 会额外返回 `origin_lidar`（多车合并点云），用于叠加 GT 检查投影是否正确。

### 6.2 形状断言（建议加到自己的模型里）

```python
assert rm.shape[1] == 7 * self.anchor_number
assert psm.shape[2:] == rm.shape[2:]
assert psm.shape[2] * psm.shape[3] * psm.shape[1] == anchors.view(-1,7).shape[0]
```

最后一行是「空间×anchor = anchor 总数」的恒等式，能一次性抓出约束 #1。

### 6.3 快速验证数据流不改模型

建议用 **`point_pillar_early_fusion.yaml`**（`EarlyFusionDataset` + `point_pillar` 模型）跑 1 个 epoch 做冒烟测试：它只有一份合并点云，`psm` 的第 0 维恒等于 `B`，没有任何融合分支与 `record_len` 逻辑。若它也报 shape 错，问题就在 backbone/配置，而非融合模块。

⚠️ **不要**用 `point_pillar_intermediate_fusion.yaml` 做这件事：它虽然「无融合」，但输出按车数组织（不回读 `record_len`），在多车样本下会与损失维度不匹配（见 [05 §5.1](05_模型原理.md)）。

## 7. 复现 V2XSet 结果的推荐流程

README 的「三步走」策略，本质是**课程学习**（由易到难），技术基础是 `load_state_dict(strict=False)`：

| 阶段 | 配置改动 | 目的 |
|---|---|---|
| ① 完美设定 | `async: false`, `loc_err: false`, `compression: 0` | 先让模型学会融合，收敛到较高 AP |
| ② 加压缩 | `compression: 32`，续训 1~2 epoch | 让网络适应被压缩重建后的特征 |
| ③ 加噪声 | `async: true`, `async_mode: 'real'`, `async_overhead: 200~300`, `loc_err: true`, `xyz_std: 0.2`, `ryp_std: 0.2` | 学会在时延与位姿误差下鲁棒 |

> 三点提醒：① 仓库自带的 3 个含 `wild_setting` 的 yaml 都是 `async: false` / `loc_err: false` / `async_overhead: 100`，上面阶段③的值需要自己改；② `seed` 并不统一（V2X-ViT 为 `25`，CoBEVT / Where2comm 为 `20`），做对比实验前先对齐；③ `loc_err` 只在**非 ego** 车上加噪声（`basedataset.py:445`），ego 位姿永远干净。
>
> **测试时用阶段③的模型同时评 perfect 与 noisy 两个设定**，且 **`seed` 必须保持一致**，否则与其他论文的数字不可比。

## 8. 已知实现局限（改进空间）

| 局限 | 影响 | 可行的改进方向 |
|---|---|---|
| 中间融合不做数据增强 | 易过拟合 | 在投影后、体素化前对**所有车**同步施加全局变换 |
| 单一固定 anchor（3.9×1.6×1.56） | 对卡车/公交召回差 | 多尺度 anchor 或改用 CenterPoint 式无锚框 |
| 检测头不加激活、无 IoU 分支 | 置信度校准差 | 加 IoU-aware 分支 |
| CoAlign 仅含融合 | 无法复现论文位姿纠错 | 接入 `coalign` 官方仓库的训练逻辑 |
| V2VAM 的噪声模块未接入 forward | 通信鲁棒性实验无法复现 | 在 forward 中调用 `data_dropout` / `transmission_with_noise` |
| 评估只算 AP，无 mAP/Recall 曲线持久化 | 分析不充分 | `eval_utils` 已返回 `mrec/mpre`，可落盘为 PR 曲线 |
| `add_loc_noise` 每次调用都 `np.random.seed(seed)` | ① 所有车/所有帧的定位噪声**完全相同**，不是逐帧随机；② 重置全局 numpy 随机状态，影响数据增强 | 改用 `np.random.default_rng()` 局部生成器，并按 (frame, cav) 派生种子 |

---

## 9. 一句话总结

> OpenCOOD 的可扩展性来自「**配置反射 + 三段式模型契约**」；它的调试成本则来自「**几何与分辨率的隐式耦合**」。前者让你能在半小时内接入一个新融合算子，后者要求你在改 `voxel_size`、`shrink_header`、`feature_stride` 三者中任意一个时，**同时改动另外两个**并重新核对 anchor 数量。
