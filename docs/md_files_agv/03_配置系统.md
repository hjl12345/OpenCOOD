# 03 配置系统

## 1. 设计哲学

OpenCOOD 采用**单一配置源**（single source of truth）：一个 yaml 文件同时决定

- 数据集类别与路径、数据增强策略
- 预处理器（点云 → 体素 / BEV）
- 后处理器（anchor 尺寸、正负样本阈值、NMS 阈值）
- 模型结构（backbone 层数、融合模块超参、检测头通道数）
- 损失函数、优化器、学习率调度
- 噪声模拟（时延 / 定位误差 / 传输带宽）

训练脚本只有 **4 个命令行参数**（`--hypes_yaml` / `--model_dir` / `--half` / `--dist_url`），除此之外**不硬编码任何超参**——`batch_size`、`epoches`、学习率、优化器全部从 yaml 读。这是它能容纳十余种方法的原因：差异都收敛到配置里。分布式所需的 `rank / world_size / gpu` 由 `multi_gpu_utils.init_distributed_mode` 从环境变量读取，也不走命令行。

## 2. yaml 骨架

以 `hypes_yaml/point_pillar_v2vnet.yaml` 为例，逐段说明：

```yaml
name: point_pillar_v2vnet          # 实验名，决定 logs/ 下文件夹前缀
root_dir: 'opv2v_data_dumping/train'      # 训练集根目录

yaml_parser: "load_point_pillar_params"      # 派生量计算函数名（可选）
```

| 段落 | 作用 | 消费者 |
|---|---|---|

| `yaml_parser` | 加载后立即执行的派生函数 | `yaml_utils.load_yaml` |
| `train_params` | `batch_size`、`epoches`、`eval_freq`、`save_freq`、`max_cav` | `train.py` / `BaseDataset` |
| `fusion` | 融合范式 + `proj_first`、`cur_ego_pose_flag` | `build_dataset` / `IntermediateFusionDataset` |
| `preprocess` | 体素尺寸、每体素最大点数、最大体素数、LiDAR 范围 | `build_preprocessor` |
| `data_augment` | 增强算子列表 | `DataAugmentor` |
| `postprocess` | anchor 尺寸/朝向/数量、IoU 阈值、NMS、最大目标数 | `build_postprocessor` |
| `model` | `core_method` + `args` 超参树 | `create_model` |
| `loss` | `core_method` + 权重 | `create_loss` |
| `optimizer` / `lr_scheduler` | 优化器与调度器 | `setup_optimizer` / `setup_lr_schedular` |
| `wild_setting` | 时延/定位误差/传输模拟（可选） | `BaseDataset` |

## 3. 加载链路与「派生量」

`yaml_utils.load_yaml()` 做了两件事（`yaml_utils.py:14-49`）：

1. **路径覆盖**：若传入了 `--model_dir`，**直接丢弃 `--hypes_yaml`**，改读 `<model_dir>/config.yaml`。
   → 这意味着**续训/测试时改 yaml 必须改 checkpoint 目录里的那份**，改原配置无效。这是最常见的困惑点。
2. **派生量计算**：若存在 `yaml_parser` 字段，用 `eval()` 调用同名函数。

### 3.1 `load_point_pillar_params` 干了什么

输入 `cav_lidar_range` 与 `voxel_size`，输出网格尺寸与 anchor 网格：

```python
# yaml_utils.py:109-134
grid_size = (range[3:6] - range[0:3]) / voxel_size        # → 填入 model.args.point_pillar_scatter.grid_size
anchor_args['W'] = ceil((range[3] - range[0]) / vw)        # → 检测头网格宽
anchor_args['H'] = ceil((range[4] - range[1]) / vh)        # → 检测头网格高
anchor_args['D'] = ceil((range[5] - range[2]) / vd)
```

**数值实例**（±40 m 的 PointPillar 配置，如 `point_pillar_v2vnet`）：

| 量 | 计算 | 结果 |
|---|---|---|
| LiDAR 范围 | `[-140.8, -40, -3] → [140.8, 40, 1]` | 281.6 m × 80 m × 4 m |
| 体素尺寸 | `[0.4, 0.4, 4]` | — |
| `grid_size` (nx, ny, nz) | `(281.6/0.4, 80/0.4, 4/4)` | **704 × 200 × 1** |
| BEV 张量 | (B, C, ny, nx) | **(B, 64, 200, 704)** |
| anchor 网格 `W × H` | `ceil(281.6/0.4) × ceil(80/0.4)` | **704 × 200** |

> ⚠️ 这些数字**只对 ±40 m 配置成立**。V2X-ViT / CoBEVT / Where2comm 用 ±38.4 m（`ny=192`），Late Fusion 用 `x∈[-70.4, 70.4]`（`nx=352`），完整对照见 §3.2。

> 注意：`grid_size` 用 `np.round`，`W/H` 用 `math.ceil`。当范围/体素不能整除时两者可能相差 1，这是历史遗留的不一致，改 `voxel_size` 时需自查。

### 3.2 anchor 网格 ≠ 检测头分辨率

`postprocess.anchor_args` 里还有一个 **`feature_stride`**，anchor 实际建立在**降采样后**的网格上：

```python
# voxel_postprocessor.py:53-54
x = np.linspace(xrange[0]+vw, xrange[1]-vw, W // feature_stride)
y = np.linspace(yrange[0]+vh, yrange[1]-vh, H // feature_stride)
```

因此：

```
anchor 网格 = (W // feature_stride) × (H // feature_stride) × anchor_num
```

**而检测头的输出分辨率由 `model.args.shrink_header.stride` 决定**（`DownsampleConv` 的第一层 conv stride）。两者必须相等，否则 `delta_to_boxes3d` 处形状不匹配。

更准确的关系是：

```
anchor 的 feature_stride = 2 × shrink_header.stride
                            └─ 那个 2 来自 BEV Backbone 自身：三尺度特征最后都被
                               上采样回 BEV 的 1/2 分辨率，所以即使没有 shrink_header，
                               检测头也已经比 BEV 小一半
```

于是「4↔2」与「2↔1（含无 shrink）」两种组合都成立——**忘了 backbone 自带 /2 是这里最常见的误算**。

各配置的实际取值（已用 `yaml_utils.load_yaml` 实测，全部自洽）：

| 配置 | LiDAR 范围 y | BEV (nx×ny) | `feature_stride` | anchor 网格 | `shrink stride` | `psm`/`rm` 分辨率 |
|---|---|---|---|---|---|---|
| `point_pillar_v2vnet` | ±40 | 704 × 200 | 4 | 176 × 50 | 2 | 176 × 50 ✅ |
| `point_pillar_v2xvit` | ±38.4 | 704 × **192** | 4 | 176 × **48** | 2 | 176 × 48 ✅ |
| `point_pillar_cobevt` | ±38.4 | 704 × **192** | 4 | 176 × **48** | 2 | 176 × 48 ✅ |
| `point_pillar_where2comm` | ±38.4 | 704 × **192** | 4 | 176 × **48** | 2 | 176 × 48 ✅ |
| `point_pillar_intermediate_V2VAM` | ±40 | 704 × 200 | 4 | 176 × 50 | 2 | 176 × 50 ✅ |
| `point_pillar_fcooper` | ±40 | 704 × 200 | 2 | 352 × 100 | 1 | 352 × 100 ✅ |
| `point_pillar_coalign` | ±40 | 704 × 200 | 2 | 352 × 100 | 无 shrink（384 直连） | 352 × 100 ✅ |
| `point_pillar_intermediate`（无融合） | ±40 | 704 × 200 | 2 | 352 × 100 | 无 shrink（384 直连） | 352 × 100 ✅ |
| `point_pillar_late_fusion` | ±40（x 仅 ±70.4） | **352** × 200 | 2 | 176 × 100 | 无 shrink（384 直连） | 176 × 100 ✅ |

> ⚠️ 本表只验证「形状自洽」，不代表「能跑通」。`point_pillar_coalign` 的形状是对的，但模型在 `__init__` 就会因 `compression: 0` 触发 `ZeroDivisionError`（见 [07 §5.6](07_扩展与注意事项.md)）。

> 上表仅覆盖 PointPillar 系列（其它 backbone 走各自的 `yaml_parser` 与前/后处理，网格推导规则不同）。例如 `voxelnet_intermediate_fusion` 的范围是 ±41.6 m、`voxel_size=[0.4,0.4,0.4]`，故 `ny = 208`、anchor 网格为 `352×104`，且 z 向有 10 层体素；SECOND / PIXOR 又各有自己的 `grid_size` 字段。

> 这张表说明两件事：
> 1. **同一份代码在不同 yaml 下网格不同**，`704×200` 只是「±40 m 配置」的值，不是全局常量；
> 2. V2X-ViT 系列用 ±38.4（`ny=192`）而多数配置用 ±40（`ny=200`）。这一差异**在效果上是必要的**：`PyramidWindowAttention` 要把特征图切成 `4/8/16` 的窗口，`H'=48` 三者皆可整除，而 `H'=50` 连 `window_size=4` 都不满足，会直接抛 `einops` 维度错误。**改 LiDAR 范围时必须同时检查窗口整除性。**

> 这就是 [README](README.md) 里那条「一句话警告」的来源。

## 4. anchor 与正负样本定义

`VoxelPostprocessor.generate_anchor_box()`（`voxel_postprocessor.py:28-76`）：

- 单一尺寸：`l=3.9, w=1.6, h=1.56`（一辆典型轿车），`r=[0, 90]` 两档朝向 → `anchor_num=2`
- 中心 z 固定为 `-1.0` m：体素在 z 方向只有 1 层，anchor 的高度中心无分辨率可言，网络只需从该固定基准回归 **z 的相对偏移**（`tz = (gz - az)/ah`）
- 输出 `(H', W', anchor_num, 7)`，顺序 **`hwl`**（`[cx, cy, cz, h, w, l, yaw]`，其中 `H'=H//feature_stride`、`W'=W//feature_stride`）

正负样本分配（`voxel_postprocessor.py:140-192`）：

| 规则 | 条件 | 结果 |
|---|---|---|
| 正样本 | 2D IoU > `pos_threshold`(0.6) | `pos_equal_one=1` |
| 强制正样本 | 每个 GT 的最高 IoU anchor（IoU>0 即可） | 保证召回 |
| 负样本 | 与**所有** GT 的 IoU 均 < `neg_threshold`(0.45) | `neg_equal_one=1` |
| 忽略区 | 介于两者之间 | 不参与分类损失 |
| 冲突修正 | 最高 IoU 的 anchor 不允许同时为负 | 置 `neg=0` |

回归编码（`voxel_postprocessor.py:167-183`）：

```
tx = (gx - ax) / d,  ty = (gy - ay) / d,  tz = (gz - az) / ah
th = log(gh / ah),   tw = log(gw / aw),   tl = log(gl / al)
tr = gr - ar
其中 d = sqrt(aw² + al²) 为 anchor 底面对角线
```

解码是严格逆运算，见 `delta_to_boxes3d`（`voxel_postprocessor.py:349-401`）。

## 5. 噪声模拟：`wild_setting`

这是复现 V2XSet「noisy setting」结果的关键段（`basedataset.py:70-105, 345-402`）。

**只有 3 个 yaml 含该段**：`point_pillar_cobevt`、`point_pillar_v2xvit`、`point_pillar_where2comm`。下面就是 `point_pillar_v2xvit.yaml:1-11` 的原文（注意 `async` / `loc_err` 默认都是 **false**，即仓库自带配置是「完美设定」）：

```yaml
wild_setting:
  async: false           # 是否启用通信时延
  async_mode: 'sim'      # sim: 常数时延；real: 均匀分布 + 传输 + 计算耗时
  async_overhead: 100    # 系统异步上界（ms）
  seed: 25               # ★ 与论文对齐时不要改
  loc_err: false         # 是否注入 GPS 误差
  xyz_std: 0.2           # 位置噪声标准差（m）
  ryp_std: 0.2           # 航向角噪声标准差（rad）
  data_size: 1.06        # 传输数据量（Mb），仅 real 模式
  transmission_speed: 27 # 带宽（Mb/s）
  backbone_delay: 10     # backbone 计算耗时（ms），仅 real 模式
```

> **`seed` 三个配置并不一致**：V2X-ViT 是 `25`，CoBEVT 与 Where2comm 是 `20`。做对比实验时应统一为同一个值，否则噪声采样不同、数字不可比。
>
> 缺少 `wild_setting` 的配置会走 `basedataset.py:96-105` 的 else 分支：`async_flag=False`、`async_overhead=0`、`loc_err_flag=False`。也就是说**噪声是「不写即关」**，想跑 noisy setting 必须自己加这一段并把 `async`/`loc_err` 改成 `true`。
>
> 仓库里没有出现 `300`（系统异步上界）这一取值；`300` 是论文/README 里 noisy setting 的常用设定，需要时自行填写。

时延计算（`basedataset.py:363-376`）：

```python
if async_mode == 'real':
    time_delay = uniform(0, async_overhead) + data_size/transmission_speed*1000 + backbone_delay
else:
    time_delay = abs(async_overhead)
time_delay = int(time_delay) // 100     # ms → 帧（10 Hz，1 帧 = 100 ms）
```

时延的作用方式：该车的点云取 `timestamp - time_delay` 帧，但**标注（GT）仍用当前帧**（`basedataset.py:469`：`delay_params['vehicles'] = cur_params['vehicles']`）。这样保证评估公平——预测的是「当前时刻」的目标，而输入故意滞后。

定位误差（`basedataset.py:378-402, 445-451`）：仅对**非 ego** 车、在其位姿上叠加高斯噪声，且只扰动 `x/y/z` 与 **yaw**（`roll`、`pitch` 原样保留）。

> ⚠️ 这里有个容易误读的实现细节：`add_loc_noise` 一进来就 `np.random.seed(self.seed)`，所以**每次调用得到的是同一组噪声向量**——同一 `seed` 下，所有非 ego 车、所有帧都加上**完全相同**的偏移（并非逐帧独立的随机误差）。想让每帧不同，必须去掉这行 seed 或改用 `np.random.default_rng()`。
>
> 副作用：`np.random.seed()` 会重置全局 numpy 随机状态，影响同进程内的其它随机性（如数据增强）。若做严格可复现实验，需注意调用顺序。

## 6. 训练期配置消费

```python
# tools/train.py:36-133
hypes = yaml_utils.load_yaml(opt.hypes_yaml, opt)     # 加载 + 派生
opencood_train_dataset = build_dataset(hypes, visualize=False, train=True)
model      = train_utils.create_model(hypes)          # 反射
criterion  = train_utils.create_loss(hypes)           # 反射
optimizer  = train_utils.setup_optimizer(hypes, model)
scheduler  = train_utils.setup_lr_schedular(hypes, optimizer, num_steps)
```

支持的调度器（`train_utils.py:202-256`）：

| `core_method` | 类 | 说明 |
|---|---|---|
| `step` | `StepLR` | 按 epoch 阶梯衰减 |
| `multistep` | `MultiStepLR` | `step_size: [10, 15]` 指定里程碑 |
| `exponential` | `ExponentialLR` | 指数衰减 |
| `cosineannealwarm` | `timm` 的 `CosineLRScheduler` | 按 **iteration** 更新，需调用 `step_update()`，与其它三者调用方式不同 |

> 代码中有一处易错分支（`train.py:128-131`）：非 cosine 调度器用 `scheduler.step(epoch)`，cosine 用 `scheduler.step_update(epoch*num_steps+i)`。若自定义调度器，需在此处添加分支。

## 7. 产物与续训

| 项 | 位置 |
|---|---|
| 日志目录 | `opencood/logs/<name>_<YYYY_MM_DD_HH_MM_SS>/` |
| 配置快照 | 上述目录下 `config.yaml` |
| 权重 | `net_epoch{N}.pth`（每 `save_freq` 个 epoch） |
| TensorBoard | 同目录（`SummaryWriter(saved_path)`） |
| 评估结果 | 推理时写入 `model_dir` 下 |

续训逻辑（`train_utils.py:18-64`）：扫描 `*epoch*.pth` 取最大 epoch，若存在 `latest.pth` 则优先；**`load_state_dict(strict=False)`**，因此结构微调后仍能加载（缺失层随机初始化，多余层忽略）。

> 这正是「先空场景训练 → 再加 compression → 再开 async」三步走策略能实现的技术基础（README 的 V2XSet 训练说明）：stage 1 训练出的 backbone 权重，stage 2 因多出 `naive_compressor` 层而部分匹配，仍可续训。
