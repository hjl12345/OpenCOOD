# 05 模型工作原理

## 1. 统一范式：backbone + fusion + head

**多数**中间融合模型共享同一条三段式结构，差异主要在中间一段（CoAlign 略有不同：多尺度分别融合，见 §5.8）：

```
                   ┌─────────────── 每辆车独立执行 ───────────────┐
voxel_features ──→ │ PillarVFE → Scatter → BEVBackbone → shrink │ ──→ (ΣM,64) → (N,64,192,704) → (N,384,96,352) → (N,256,H',W')
                   └───────────────────────────────────────────────┘
                                        ↓ regroup(record_len)
                              (B, L, 256, H', W')   ← 多车特征 + mask
                                        ↓ ★ fusion_net（各模型的主要差异）
                              (B, 256, H', W')      ← ego 视角的融合特征
                                        ↓ cls_head / reg_head (1×1 conv)
                              psm (B, 2, H', W'),  rm (B, 14, H', W')
```

> 上图的 `192/96/48` 是 **V2X-ViT 配置（±38.4 m）** 的值；±40 m 配置则为 `200/100/50`，Late Fusion 为 `200×352 → 100×176`。具体见 [03 §3.2](03_配置系统.md) 的对照表。

这个「特征提取与融合解耦」的设计带来两个直接后果：

1. **公平性**：**同一份 yaml 下**换融合模块时，参数量与感受野一致，AP 差异可归因于融合策略；
2. **局限性**：所有 PointPillar 方法共享同一量化误差（0.4 m 体素），无法体现「更精细 backbone + 更弱融合」的对比。

## 2. Backbone 三段详解

### 2.1 PillarVFE：支柱内点特征编码

`models/sub_modules/pillar_vfe.py`。输入 `(M, 32, 4)`（M 个非空体素 × 最多 32 点 × (x,y,z,intensity)），输出 `(M, 64)`。

**第一步：逐点构造 10 维特征**（`pillar_vfe.py:105-135`）

| 特征组 | 维度 | 公式 | 物理含义 |
|---|---|---|---|
| 原始坐标 + 反射强度 | 4 | `[x, y, z, i]` | 绝对位置 |
| `f_cluster` | 3 | `p - mean(p_in_voxel)` | **点相对体素中心的偏移** |
| `f_center` | 3 | `p - center(voxel_idx)` | **点相对体素几何中心的偏移** |

（配置 `use_absolute_xyz: true` 使 `num_point_features` 从 4 增到 10；`with_distance: false` 关闭第 11 维的径向距离。）

**第二步：padding mask**：`get_paddings_indicator` 把 `voxel_num_points` 之外的补零位置屏蔽，避免零值污染池化。

**第三步：PFNLayer（PointNet 式）**（`pillar_vfe.py:10-53`）

```
Linear(10 → 64) → BatchNorm1d → ReLU → max over points
```

`num_filters: [64]` 只有一层，因此无「max 特征回拼」分支。最终每个体素得到 **1 个 64 维向量**。

> 工程细节（`pillar_vfe.py:29-44`）：两处与「大 batch」有关的补丁——① 当支柱数 > `part=50000` 时把 Linear 分段执行（注释称 nn.Linear 在超大 batch 下结果不稳定）；② 在 BatchNorm 前后临时 `torch.backends.cudnn.enabled = False/True`，规避 cuDNN 对 1D BN 的数值不稳定（注意它是**全局开关**，会短暂影响其它算子）。

### 2.2 PointPillarScatter：稀疏 → 稠密

`models/sub_modules/point_pillar_scatter.py`。把 `(M, 64)` 的支柱特征按坐标散射回稠密 BEV 张量，空位置补 0。输出第一维**不是 batch**，而是 `coords[:,0].max()+1`——中间融合里它是 `Σn_cav`（每辆车一张 BEV 图）；下面按 ±40 m 配置写作 `(Σn, 64, 200, 704)`：

```python
indices = coords[:,1] + coords[:,2]*nx + coords[:,3]
#   coords = [entry, z, y, x] → 索引 = z + y*nx + x
#   标准公式是 z*nx*ny + y*nx + x，代码省掉了 *nx*ny，因为 nz==1 被 assert、z 恒为 0
spatial_feature[:, indices] = pillars.t()
```

> **坐标顺序陷阱**：`coords` 是 `[batch, z, y, x]`，不是 `[batch, x, y, z]`。这一点在 `PillarVFE` 中已交叉验证（`f_center` 用 `coords[:,3]*voxel_x`）。

### 2.3 BaseBEVBackbone：2D CNN + FPN

`models/sub_modules/base_bev_backbone.py`。按 `layer_nums=[3,5,8]`、`layer_strides=[2,2,2]`、`num_filters=[64,128,256]`（下表以 ±40 m 配置的 `200×704` 输入为例，±38.4 m 配置则为 `192×704`）：

| 阶段 | 输入 | 操作 | 输出 |
|---|---|---|---|
| block1 | 64@200×704 | ZeroPad2d(1) + Conv3×3/s2(pad0) + BN/ReLU + 3×(Conv3×3+BN+ReLU) | 64@100×352 |
| block2 | 64@100×352 | ZeroPad2d(1) + Conv3×3/s2 + 5×Conv | 128@50×176 |
| block3 | 128@50×176 | ZeroPad2d(1) + Conv3×3/s2 + 8×Conv | 256@25×88 |
| deblock1 | 64@100×352 | ConvTranspose(k=1,s=1) → 128 | 128@100×352 |
| deblock2 | 128@50×176 | ConvTranspose(k=2,s=2) → 128 | 128@100×352 |
| deblock3 | 256@25×88 | ConvTranspose(k=4,s=4) → 128 | 128@100×352 |
| **concat** | — | 通道拼接 | **384@100×352** |

> 三个 block **都**用 `ZeroPad2d(1) + Conv(padding=0, stride=2)` 组合来实现「same-ish」下采样（先补 1 圈再卷积，避免尺寸掉得过多）；`layer_nums=[3,5,8]` 是每个 block 里**额外的**同分辨率卷积层数。

即：三尺度特征全部上采样回 **1/2 分辨率**（相对 BEV）后拼接，输出通道数 = `sum(num_upsample_filter)`（本仓库各配置均为 `128×3 = 384`），空间尺寸随输入变化：`192×704 → 96×352`，`200×352 → 100×176`。

> `point_pillar_intermediate`（无融合模型）用的是 `AttBEVBackbone`，`point_pillar_coalign` 用的是 `ResBEVBackbone`，二者 FPN 拓扑相同（输出同为 384@1/2 分辨率），但 block 内部结构不同。

### 2.4 shrink_header：为融合降本

`models/sub_modules/downsample_conv.py`。`DoubleConv = Conv(k,stride,pad) → ReLU → Conv3×3 → ReLU`。

| 配置 | `kernal_size/stride/padding` | 作用 | 输出 |
|---|---|---|---|
| V2VNet / V2X-ViT / CoBEVT / Where2comm / V2VAM | `[3]/[2]/[1]` | 通道 384→256 **且** 分辨率减半 | 256@(H/2)×(W/2) |
| F-Cooper | `[1]/[1]/[0]` | 仅通道 384→256，分辨率不变 | 256@H×W |
| CoAlign / point_pillar_intermediate | **无 `shrink_header`** | 384 通道直连检测头 | 384@H×W |

这一步同时决定了**检测头分辨率**，必须与 `anchor_args.feature_stride` 一致（见 [03 配置系统](03_配置系统.md) §3.2）。

### 2.5 通信压缩（可选）

`compression > 0` 时插入 `NaiveCompressor(input_dim, rate)`（`naive_compress.py`）：

```
encoder: Conv3×3(256 → 256//rate) → BN → ReLU
decoder: Conv3×3(256//rate → 256) → BN → ReLU → Conv3×3(256 → 256) → BN → ReLU
```

即一个 **3×3 卷积自编码器**（不是 1×1、也不是反卷积），作用是模拟「发送端压缩 → 接收端重建」的有损链路。带宽近似正比于通道数，因此：

- `rate=32` → `256/32 = 8` 通道 → 约为原始带宽的 1/32（CoAlign 的 `72.08 / 2.24 Mb` 就是这么来的）；
- `rate=64` → `4` 通道 → 约 1/64（V2VNet / F-Cooper / CoBEVT 的 `72.08 / 1.12 Mb`）。

> 注意 `input_dim // rate` 是**整除**，当 `rate` 不能整除 256 时会静默取整；且压缩只作用于通道维、不改变空间分辨率。

## 3. 检测头

```python
self.cls_head = nn.Conv2d(256, anchor_number, kernel_size=1)       # → psm: (B, 2, H', W')
self.reg_head = nn.Conv2d(256, 7 * anchor_number, kernel_size=1)   # → rm:  (B, 14, H', W')
```

> 输入通道**不是**常数：V2VNet / V2X-ViT / F-Cooper / Where2comm / V2VAM 是 `256`（= `shrink_header.dim[-1]`）；`point_pillar`、`point_pillar_intermediate`、`point_pillar_coalign` 是 `128*3 = 384`（无 shrink）；CoBEVT 与 V2VAM 直接写死 `128*2 = 256`，改 backbone 滤波数时这两处最容易被漏改。

- **anchor-free 的外观，anchor-based 的本质**：分类分支给每个 anchor 一个前景 logit，回归分支给 7 个偏移量，不是 CenterPoint 那种 heatmap。
- 每个网格 2 个 anchor（朝向 0° / 90°），尺度固定 3.9×1.6×1.56 m。
- 输出**不加激活**：训练时用 logits 直接算 focal loss，推理时才 `sigmoid`。

解码（`voxel_postprocessor.py:349-401`）：

```
cx = tx·d + ax,  cy = ty·d + ay,  cz = tz·ah + az
h  = exp(th)·ah, w = exp(tw)·aw, l = exp(tl)·al
yaw = tr + ar                 d = sqrt(aw² + al²)
```

## 4. 融合模块分类学

在进入逐个讲解前，先建立一张对照表——**所有融合模块都在回答三个问题**：

| 问题 | 选项 | 代表 |
|---|---|---|
| **Q1. 在哪对齐几何？** | 点云级（`proj_first=True`）/ 特征级 warp / 让注意力自己学 | 多数 / V2VNet、V2X-ViT / F-Cooper、AttFusion |
| **Q2. 如何聚合？** | max / 逐像素 attention / 图消息传递 / 全局 Transformer | F-Cooper / AttFusion / V2VNet / V2X-ViT |
| **Q3. 传什么、传多少？** | 全量特征 / 压缩特征 / 空间稀疏选择 | 全部 / NaiveCompressor / Where2comm |

| 模块 | 文件 | Q1 对齐 | Q2 聚合 | 额外输入 | 复杂度 |
|---|---|---|---|---|---|
| 无融合 | — | — | **不聚合**（按车各自出预测） | — | O(1) |
| F-Cooper | `f_cooper_fuse.py` | 点云级 | `max(dim=L)` | — | O(L·HW) |
| Attentive | `self_attn.py` | 点云级 | 逐像素 softmax attention | — | O(L²·HW) |
| V2VNet | `v2v_fuse.py` | 特征级 warp | ROI 加权 + mean + ConvGRU×2 | `pairwise_t_matrix` | O(L²·HW) × 迭代 |
| V2X-ViT | `v2xvit_basic.py` | STTF warp | 异构 agent attention + 窗口 attention | `prior_encoding`、`spatial_correction_matrix` | O(L²·HW) + O(HW·w²) |
| CoBEVT | `swap_fusion_modules.py` | 点云级 | FAX 轴向注意力（window + grid） | — | O(HW·w²) |
| Where2comm | `where2comm_fuse.py` | 点云级 | 逐像素 attention × **通信 mask** | 单智能体置信图 | O(L²·HW·ρ) |
| CoAlign | `coalign_fuse.py` | 特征级 warp（逐尺度） | 逐像素 attention | `pairwise_t_matrix` | O(3·L²·HW) |
| V2VAM | `V2VAM.py` | 点云级 | 十字交叉注意力 + max/avg 双池化 | — | O(L·HW·(H+W)) |

> 表中「点云级 / 特征级 warp」是**算法设计**的分类。落到本仓库的实际运行：**所有 yaml 都走 `proj_first=True`（点云级对齐），因此 V2VNet / CoAlign 里的特征级 warp 参数恒为单位矩阵**，运行时等价于「不对齐」。见 §5.4 与 §5.8 的说明。

## 5. 逐个详解

### 5.1 「无融合」模型（`point_pillar_intermediate`）

`point_pillar_intermediate.py` **没有任何 fusion 模块**：backbone 之后直接过检测头（用 `AttBEVBackbone`，头部 384 通道）。

但它并不是一个可直接使用的 no-fusion 基线，原因在于**它不读 `record_len`**：

- `PointPillarScatter` 按「车级条目」散射，所以 `psm` 的第 0 维是 **Σn_cav（本 batch 所有车的总数）**，而非 `B`；
- 而损失函数用 `pos_equal_one.view(psm.shape[0], -1)`（`point_pillar_loss.py:97-98`）对齐，标签总数却是 `B × H' × W' × 2`；
- 只有「每条样本恰好 1 辆车」（`Σn_cav == B`）时两者才一致。OPV2V/V2XSet 的场景普遍含多车，此时 `view` 会直接失败。
- 推理期同样不成立：`VoxelPostprocessor.post_process` 里有 `prob.reshape(1, -1)` 与 `assert batch_box3d.shape[0] == 1`，而 `psm` 的第 0 维是多车，会报 shape 不匹配或断言失败。

因此 `point_pillar_intermediate_fusion.yaml` 更接近**遗留占位配置**，不宜作为协同增益的 no-fusion 对照。若需要单车基线，`point_pillar_early_fusion.yaml`（单份合并点云，`N == B`）或 `point_pillar_late_fusion.yaml`（训练时每样本随机取 1 车）才是能跑通的路径。

> 该结论由代码静态推断（未在真实数据上实测），因为本仓库不附带数据。使用前请先跑一个小 batch 验证。

### 5.2 F-Cooper：逐像素最大池化

`f_cooper_fuse.py`：三行核心逻辑。

```python
split_x = regroup(x, record_len)          # [(n1,C,H,W), (n2,C,H,W), ...]
out = [torch.max(xx, dim=0, keepdim=True)[0] for xx in split_x]
```

即：**对每个 BEV 像素，在车辆维度取最大值**。物理直觉是「哪辆车在该位置看到了东西，就采用它的响应」。

- 优点：零参数、极快、对位姿误差不敏感（只要点云已对齐）。
- 缺点：max 会放大噪声与离群响应；无法处理「多车互补」的加权融合。

### 5.3 Attentive Fusion：逐像素跨车自注意力

`self_attn.py:46-66`。与常见 Transformer 不同，它的**注意力在车辆维、token 是通道向量**：

```python
xx = xx.view(cav_num, C, -1).permute(2, 0, 1)   # (H*W, L, C)
h  = att(xx, xx, xx)                             # 每个像素独立做 L×L 注意力
h  = h.permute(1, 2, 0).view(cav_num, C, W, H)[0, ...]  # 取 ego（index 0）
```

> 注意原码中局部变量名把 `H/W` 写反了（`C, W, H = split_x[0].shape[1:]`），但 `view` 的目标形状同样用反写的 `(W, H)`，两者恰好抵消，实际形状是正确的 `(C, 48, 176)`（±40 m 配置下为 `(C, 50, 176)`）。改写时**不要「顺手纠正」这个命名**，否则会真的把宽高颠倒。

即：在同一个空间位置上，让 ego 的通道向量去「查询」其他车的通道向量，学习加权组合。**没有位置编码、没有多头**，是极简版 cross-agent attention。

> 优点：能学到「信任哪辆车」；缺点：每个像素独立，缺乏空间上下文，且 O(L²·HW) 的显存开销在大 BEV 上偏高。

### 5.4 V2VNet：位姿引导 warp + ConvGRU 迭代消息传递

`v2v_fuse.py:51-150`。**这是理解「特征级对齐」的最佳范例**（但请注意下面的前提说明）。

```python
for iteration in range(num_iteration):        # 默认 2 轮
    for i in range(N):                        # 每个节点（车）
        # ① 用 pairwise_t_matrix[:, i] 把邻居特征 warp 到 i 的坐标系
        neighbor = warp_affine(all_features, T[:, i], (H, W))     # (N,C,H,W)
        # ② 拼上节点自身的特征（repeat N 份）→ (N,2C,H,W)
        msg = msg_cnn(cat([neighbor, ego_feat.repeat(N,1,1,1)]))  # 3×3 conv → (N,C,H,W)
        # ③ 用旋转 ROI mask 屏蔽「视野外/无效区域」
        msg = msg * roi_mask
        # ④ 聚合
        agg = mean(msg, dim=0)                                    # (C,H,W)
        # ⑤ 用 ConvGRU 更新节点状态
        out_i = conv_gru(cat([feat_i, agg]))                      # hidden 256
    # ⑥ 仅在最后一轮取 ego 的输出
```

> ⚠️ **本仓库所有 yaml 都是 `proj_first=True`，`pairwise_t_matrix` 恒为全 I**，所以上面 ① 的 warp 实际是恒等映射、③ 的 ROI mask 也退化成「整个 FOV」。换句话说，**开箱即用的 V2VNet 是「无几何对齐 + 邻居特征聚合 + 2 轮 GRU」**；要复现论文的特征级 warp，需在 yaml 里显式写 `fusion.args.proj_first: false`（同时会遇到 [07 §2](07_扩展与注意事项.md) 约束 #16 的索引错位问题）。

三个关键设计：

1. **显式几何**：`get_discretized_transformation_matrix` 把 4×4 连续变换转成「像素单位的平移+旋转」，再 `grid_sample` 做双线性 warp。这要求 `downsample_rate` 与特征分辨率严格对应（配置里 `downsample_rate: 4`，`conv_gru.H/W: 50/176`）。
2. **ROI mask**：`get_rotated_roi` 生成旋转矩形掩码，屏蔽邻居车视野之外的区域——否则 warp 会引入大量「不存在的特征」。
3. **迭代 refinement**：`num_iteration=2` 让信息传播两跳（ego←邻居←邻居的邻居），等价于聚合更大范围的协同图。

> 代价：需要完整 `pairwise_t_matrix`，对定位误差敏感（这正是 CoAlign 要解决的问题）。

### 5.5 V2X-ViT：STTF 纠偏 + 异构注意力 + 多尺度窗口注意力

`v2xvit_basic.py`，结构最复杂，也是本仓库的旗舰实现。数据流（`point_pillar_transformer.py:71-122`）：

```
regroup → (B,L,256,48,176)                      ← V2X-ViT 配置：BEV 192×704 → /4
prior_encoding (B,L,3,1,1) ─repeat→ (B,L,3,48,176) ─cat ch→ (B,L,259,48,176) ─permute→ (B,L,48,176,259)
        ↓ V2XTEncoder
  ① 拆分：x=(B,L,48,176,256), prior=(B,L,48,176,3)
  ② RTE：用 time_delay 加正弦相对时间编码            ← 显式告知「这条特征有多旧」
  ③ STTF：用 spatial_correction_matrix warp 非 ego 特征   ← 补偿「投影时刻 ≠ 接收时刻」的 ego 位移
  ④ com_mask：ROI mask × cav_mask  (B,H,W,1,L)      ← 屏蔽无效车与视野外区域（最后一维是车辆维）
  ⑤ ×3 层 encoder：每层 1 个 V2XFusionBlock + 1 个 FFN（PreNorm 残差）
        V2XFusionBlock = HGTCavAttention（跨车）+ PyramidWindowAttention（空间）
  ⑥ 取 ego：output[:, 0] → (B,48,176,256) → permute → (B,256,48,176)
```

**组件一：STTF（Spatial-Temporal Transformation）**（`v2xvit_basic.py:11-32`）

```python
dist = get_discretized_transformation_matrix(spatial_correction_matrix, 0.4, 4)
T = get_transformation_matrix(dist[:, 1:, ...], (H, W))     # 只对非 ego
cav_features = warp_affine(x[:, 1:].reshape(-1,C,H,W), T, (H,W))
x = cat([x[:, 0:1], cav_features], dim=1)                   # ego 原样保留
```

> **隐含假设：ego 必须位于 regroup 后的第 0 位**。这依赖 `scenario_database` 中 ego 排首位，因此**不能随意打乱 CAV 顺序**。

**组件二：RTE（RelTemporalEncoding）**（`v2xvit_basic.py:35-79`）：标准正弦位置编码的可学习变体，`emb(t * RTE_ratio)` 查表后过一层 Linear 加到特征上。`RTE_ratio=2` 表示「训练用 100 ms 间隔，测试可用 50 ms」，提供时延分辨率的泛化能力。

**组件三：HGTCavAttention（异构多智能体注意力）**（`hmsa.py:7-151`）

- **异构**：`num_types=2`（V2V=0 / V2I=1），为每种类型维护**独立的 Q/K/V 线性层**；
- **关系感知**：`num_relations=4 = 2×2`，为「车→车 / 车→路 / 路→车 / 路→路」四种关系各维护一组 `relation_att`（注意力权重矩阵）与 `relation_msg`（消息变换矩阵）；
- **注意力维度**：在**车辆维 L** 上做（每个 BEV 位置独立一个 L×L 注意力），与 AttFusion 思路一致，但加入了多头、类型、关系三重条件化；
- 计算形式：`att = softmax((q · W_att · kᵀ)/√d + mask)`，`out = att · (W_msg · v)`，用 `einsum` 实现。

**组件四：PyramidWindowAttention（多尺度窗口注意力）**（`mswin.py`）

- 在**空间维**上做窗口化自注意力，三档窗口 `window_size=[4,8,16]`、`heads=[16,8,4]`；
- 通过 `rearrange('b l (new_h w_h) (new_w w_w) ...')` 把特征图切成不重叠窗口，窗口内做 full attention（复杂度从 O((HW)²) 降到 O(HW·w²)）；
- 支持相对位置编码（`relative_pos_embedding: true`），并用 `split_attn` 融合不同窗口尺度。

即 V2X-ViT 的一个 block 同时做「跨车交互」与「大范围空间交互」，这正是它比纯逐像素注意力（AttFusion）显著更强的原因。

### 5.6 CoBEVT：FAX 融合轴向注意力

`swap_fusion_modules.py` 的 `SwapFusionEncoder`（文件头注释即写明 "swap fusion applications (also known as **Fused Axial Attention**)"），核心是 **FAX**：把 2D 注意力分解为「行方向 + 列方向」两段 1D 注意力（类似 Criss-Cross / Axial attention），复杂度从 O((HW)²) 降到 O(HW·(H+W))。

- `point_pillar_cobevt.py` 先 `regroup` 成 `(B,L,C,H,W)`，再把 `mask` 用 `repeat` 扩展到 `(B,H,W,1,L)` 一并传入；
- `SwapFusionBlockMask` 用 `rearrange('b (x w1) (y w2) ...', w1=window_size)` 切窗口，**要求 H、W 都能被 `window_size` 整除**；yaml 中 `window_size: 4`，因此 `H'=48` 可行，而 ±40 m 的 `H'=50` 会直接抛 rearrange 错误。改 LiDAR 范围或窗口尺寸时必须一并检查。

> ⚠️ 名称辨析：CoBEVT 的融合模块**不是** `sub_modules/vsa.py`。`vsa.py` 中的 `VoxelSetAbstraction` 属于 **FPV-RCNN** 的两阶段 PointNet 抽象，与 CoBEVT 无关。

在 LiDAR 单视图设定下，FAX 的优势不如多相机 BEV 分割任务明显，但仍是「用 Transformer 做协同」的轻量选项。

### 5.7 Where2comm：只传「有信息量」的位置

`where2comm_fuse.py`。**唯一在融合阶段做通信剪枝的方法**，思路：

```
① 单智能体先各自过检测头 → psm_single（未激活的分类 logits）
② 逐位置：先 sigmoid，再沿 anchors 维取 max → 置信度图 (L,H,W)
③ 生成通信 mask：
     训练时：随机选 K = H·W·U(0,1) 个 top-K 位置（代理目标，让网络学会「稀疏也能work」）
     测试时：阈值 threshold 二值化
     ego 的 mask 强制全 1（本地特征不压缩）
④ x = x * communication_mask
⑤ 逐像素跨车 attention 融合（同 AttFusion）
```

`multi_scale=True` 时，在 backbone 每一层都执行「mask → 融合 → deconv」，融合发生在**高分辨率**（不 shrink、不压缩），代价是带宽。

输出额外返回 `communication_rates`，可直接作为「平均通信比例」指标记录（`psm, rm, com`）。

### 5.8 CoAlign：多尺度 warp + attention（仅融合部分）

本仓库只包含**融合部分**（`point_pillar_coalign.py` 头部注释明确说明），不含论文中的位姿图优化、可微位姿估计与自监督训练。因此它**不能**复现 CoAlign 论文的「位姿纠错」能力，只能当作一个多尺度特征融合器使用。

与其它模型的四点差异：

1. backbone 换成 `ResBEVBackbone`（`res_bev_backbone` 配置段），不是 `BaseBEVBackbone`；
2. 融合网络是 `nn.ModuleList`，**每个尺度一个 `Att_w_Warp`**（`[64, 128, 256]` 通道各一个），而不是只融合最后一层；
3. 因为 yaml 中没有 `shrink_header`，`out_channel = sum(num_upsample_filter) = 128×3 = 384`，检测头直接吃 384 通道，分辨率保持 `352×100`（±40 m 配置）；
4. 每个 `Att_w_Warp` 内部流程：`warp_affine_simple`（基于 `affine_grid` + `grid_sample`）→ 展平成 `(H*W, L, C)` → `ScaledDotProductAttention` → 取 index 0（ego）。

```python
# coalign_fuse.py:64-88
t_matrix = normalized_affine_matrix[b][:N, :N]      # (N,N,2,3)
x = warp_affine_simple(batch_node_features[b], t_matrix[0], (H, W))  # 全部 warp 到 ego(0)
x = x.view(cav_num, C, -1).permute(2, 0, 1)         # (H*W, N, C)
h = self.att(x, x, x).permute(1, 2, 0).view(cav_num, C, H, W)[0, ...]
```

`normalize_pairwise_tfm` 的关键是把物理单位的 4×4 矩阵换算成 `affine_grid` 需要的归一化仿射矩阵：先取 `[0,1]` 两行与 `[0,1,3]` 三列，再按 `H/W`、`W/H` 修正长宽比例，最后把平移量除以 `(downsample_rate·discrete_ratio·W)` **再乘 2**，把米换算到 `[-1,1]`。

> ⚠️ 与 V2VNet 同理：自带 yaml 都是 `proj_first=True` → `pairwise_t_matrix` 全 I → `warp_affine_simple` 是恒等映射。CoAlign 在这里实际只做「逐尺度 attention 聚合」，几何对齐能力要等你自己引入 `proj_first=False` 与真实位姿误差才体现。
>
> ⚠️ **`point_pillar_coalign.yaml` 在本仓库直接跑不起来**：yaml 里 `compression: 0`，而 `point_pillar_coalign.py:44` 用的是 `if 'compression' in args`（键存在即为真），随后 `NaiveCompressor(64, 0)` 会做 `64 // 0` → `ZeroDivisionError`。**修法**：把该行删掉，或把判断改成 `if args.get('compression', 0) > 0`。详见 [07 §5.6](07_扩展与注意事项.md)。

### 5.9 V2VAM

`V2VAM.py:19-70`：

```
for 每辆车 i:
    ego_q = ego_k = ego_v = ego 特征
    att_i = CrissCrossAttention(ego_q, feat_i, feat_i)   # 十字交叉注意力
所有 att 在车辆维做 max + avg 双池化并相加 → cov_att（3×3 conv + BN + ReLU）
```

双池化（max + avg）是常见的「保留显著响应 + 保留平均响应」技巧。十字交叉注意力只沿当前像素的行与列展开，复杂度 O(HW·(H+W))。

> ⚠️ **batch>1 时该实现有 bug**：`att = []` 与 `out = []` 都定义在 `for xx in split_x` 循环**之外**（`V2VAM.py:35-36`），于是第 2 个样本会复用（并混入）第 1 个样本的注意力图：
> - 若两个样本车数不同 → `torch.cat` 在第 0 维形状不一致，直接 `RuntimeError`；
> - 若车数相同 → 不报错，但注意力被跨样本污染，**结果静默错误**。
>
> 而 `point_pillar_intermediate_V2VAM.yaml` 的 `batch_size` 是 **4**，因此这份配置基本无法正常训练。修法：把 `att = []` 移进 `for xx` 循环体内。

> ⚠️ 该模型文件 `import` 了 `noise` 模块的 `data_dropout / transmission_with_noise`，但 **forward 中并未调用**（已 grep 确认）。也就是说 yaml 里若配置了丢包/噪声参数，实际不生效，需自行在 `forward` 中插入。

## 6. 损失函数

`loss/point_pillar_loss.py`，总损失 = 分类 + 回归：

```
L = cls_weight · L_cls + reg_coe · L_reg        # 默认 1.0 与 2.0
```

### 6.1 分类：Focal Loss（`point_pillar_loss.py:121-125, 148-178`）

```python
alpha_weight = target·0.25 + (1-target)·0.75
pt           = target·(1-p) + (1-target)·p
focal_weight = alpha_weight · pt^2.0
bce          = max(x,0) - x·target + log(1+exp(-|x|))     # 数值稳定版 sigmoid CE
loss         = focal_weight · bce · cls_weights
```

- `cls_weights`：正负样本均为 1.0，但**整体除以正样本数**（`pos_normalizer`，`clamp(min=1)`），使不同帧的目标密度不影响梯度尺度；
- Focal 项（γ=2）抑制海量易分负样本（BEV 上 99% 以上 anchor 是背景）。

### 6.2 回归：Weighted Smooth L1 + 角度周期化（`point_pillar_loss.py:127-138, 200-212`）

```python
weights = positives / clamp(pos_normalizer, 1.0)     # 只用正样本
β = 1/9
smooth_l1(x) = 0.5x²/β  if |x| < β  else  |x| - 0.5β
```

**角度处理**（关键细节）：yaw 不直接相减，而是转成

```
pred' = sin(θp)·cos(θt),   tgt' = cos(θp)·sin(θt)
```

这样 `pred' - tgt' = sin(θp - θt)`，天然具备 2π 周期性，避免「0° 与 359° 相差很大」的错误惩罚。

### 6.3 为什么没有 IoU 分支

PointPillar 原始设计（以及本框架）**不使用 IoU-aware 或 centerness 分支**，置信度即分类概率。因此 `score_threshold` 普遍偏低（V2VNet `0.20`、V2X-ViT `0.27`），依赖后续 NMS（`0.15`）与 `GT_RANGE` 范围过滤压制误检。
