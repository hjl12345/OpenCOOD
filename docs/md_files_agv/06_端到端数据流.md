# 06 端到端数据流（含张量形状追踪）

本文以 **`point_pillar_v2xvit.yaml`** 为唯一具体案例（`max_cav=5`、`batch_size=2`、训练集 V2XSet），从磁盘文件一路追踪到 AP 数值。**所有形状均为按该 yaml 实算得到**（已用 `yaml_utils.load_yaml` 验证），可作为调试时的对照表。

> ⚠️ 换配置就换形状。V2X-ViT 的 `cav_lidar_range` 是 `[-140.8, -38.4, -3, 140.8, 38.4, 1]`，因此 `ny = 192` 而非 200，检测头分辨率是 **48×176** 而非 50×176。若你改读 `point_pillar_v2vnet.yaml`（±40 m），文中所有 `48` 应替换为 `50`、`16896` 替换为 `17600`。

## 1. 全局流程图

```mermaid
flowchart LR
    subgraph 数据
    A["scenario/CAV/ts.{pcd,yaml}"] --> B["retrieve_base_data"]
    B --> C["投影到 ego + 裁剪"]
    C --> D["SpVoxel: 体素化"]
    D --> E["collate: 拼 batch<br/>record_len / prior_encoding"]
    end
    subgraph 模型
    E --> F["PillarVFE<br/>(ΣM,4)→(ΣM,64)"]
    F --> G["Scatter<br/>→(N_pil,64,192,704)"]
    G --> H["BEV Backbone<br/>→(N_pil,384,96,352)"]
    H --> I["shrink<br/>→(N_pil,256,48,176)"]
    I --> J["regroup<br/>→(B,5,256,48,176)"]
    J --> K["V2XTransformer<br/>STTF + RTE + 3×attn"]
    K --> L["取 ego<br/>→(B,256,48,176)"]
    L --> M["cls/reg head<br/>psm, rm"]
    end
    subgraph 后处理
    M --> N["sigmoid + delta 解码<br/>→(N,16896,7)"]
    N --> O["投影 + NMS + 范围过滤"]
    O --> P["TP/FP @0.3/0.5/0.7"]
    P --> Q["eval.yaml"]
    end
```

## 2. 阶段 0：磁盘 → 原始字典

**输入**：`idx = 12345`
**输出**：`base_data_dict`（`OrderedDict`）

```
{ '1732': {ego: True,  time_delay: 0, params: {...}, lidar_np: (N₁, 4)},
  '1780': {ego: False, time_delay: 2, params: {...}, lidar_np: (N₂, 4)},
  ... }
```

| 步骤 | 动作 | 关键代码 |
|---|---|---|
| ① | 遍历 `len_record` 定位 `scenario_index`、`timestamp_index` | `basedataset.py:221-233` |
| ② | 算每车到 ego 的平面距离，写入 `distance_to_ego`；**真正按 70 m 丢弃发生在各 Dataset 的 `__getitem__` 里** | `basedataset.py:316-343`（计算）、`intermediate_fusion_dataset.py:98-105`（过滤） |
| ③ | 每车算 `time_delay`（帧），回退到 `timestamp - delay` 读点云 | `basedataset.py:245-262` |
| ④ | `reform_param` 求 `transformation_matrix = x1_to_x2(cav_pose(t-d), ego_pose(t))` | `basedataset.py:453-461` |
| ⑤ | **用当前帧 GT 覆盖延迟帧 GT**（公平评估） | `basedataset.py:469` |

> 单帧点数 `N` 随场景变化（典型 2 万~5 万点），因此与该维度相关的量都是动态的；只有 BEV 网格与 anchor 数**由配置静态决定**。

## 3. 阶段 1：样本构建（`__getitem__`）

对每辆在范围内的车执行：

```
(N,4) 点云
 ├─ shuffle_points                    # 打乱顺序
 ├─ mask_ego_points                   # 去掉打在自车车身上的点
 ├─ p[:, :3] = T @ p[:, :3]           # 投影到 ego 系（proj_first=True）
 ├─ mask_points_by_range              # 裁剪到 [-140.8,-38.4,-3,140.8,38.4,1]
 └─ preprocess                        # 体素化
      voxel_features   (M, 32, 4)
      voxel_coords     (M, 4)  [car_idx, z, y, x]
      voxel_num_points (M,)
```

`M` 上限：训练 32000 / 测试 70000（**每车**）。

同时生成标注：

```
多车 vehicles ──x1_to_x2 到 ego──→ object_bbx_center (100, 7) + mask (100,)
                                          ↓
                             generate_anchor_box() → (48, 176, 2, 7)
                                          ↓
                             generate_label() → pos/neg/targets
```

> anchor 的 H' 来自 `H // feature_stride = 192 // 4 = 48`，W' 来自 `704 // 4 = 176`。

此时 `label_dict` 的形状是**单帧的**：

| key | 形状 |
|---|---|
| `pos_equal_one` | `(48, 176, 2)` |
| `neg_equal_one` | `(48, 176, 2)` |
| `targets` | `(48, 176, 14)` |

## 4. 阶段 2：Collate（B=2, L=5）

```
2 个样本 × 每样本 n_cav 辆车 × 每车 Mᵢ 个体素
        ↓  concat（voxel_coords 第一列写入「全局车辆序号」）
voxel_features      (ΣM, 32, 4)          ΣM 上限 2×5×32000 = 32 万，实测约 10~20 万
voxel_coords        (ΣM, 4)
voxel_num_points    (ΣM,)
record_len          (2,)     例: [5, 4]
prior_encoding      (2, 5, 3)             [velocity/30, time_delay, infra]
pairwise_t_matrix   (2, 5, 5, 4, 4)       全 I（proj_first=True）
spatial_correction_matrix (2, 5, 4, 4)
label_dict.targets  (2, 48, 176, 14)
```

两个概念必须分清：

| 概念 | 含义 | 形状 |
|---|---|---|
| `record_len` | 每个**样本**有几辆车 | `(B,)` |
| `voxel_coords[:, 0]` | 该体素属于第几个**车级条目**（跨样本、跨车连续编号 `0..Σn-1`） | 标量 |

`regroup()` 用前者把打平的特征还原成 `(B, L, C, H, W)`；`PointPillarScatter` 用后者把不同车的支柱散射到**各自独立**的 BEV 图上（因此 scatter 输出第一维是 `N_pil = Σrecord_len`，而非 `B`）。

⚠️ 若样本 2 只有 4 辆车，`record_len[1]=4`，第 5 个位置的 `prior_encoding` 被补零，并在 `regroup` 中被 `mask=0` 屏蔽——**模型必须依赖 mask，不能假设 L 恒满**。

## 5. 阶段 3：Backbone 前向

| # | 模块 | 输入 | 输出 | 计算 |
|---|---|---|---|---|
| 1 | `PillarVFE` | `(ΣM, 32, 4)` | `(ΣM, 64)` | 逐点 10 维特征 → PFN(10→64) → 体素内 max |
| 2 | `PointPillarScatter` | `(ΣM, 64)` + coords | `(N_pil, 64, 192, 704)` | 按 `y*704+x` 散射，空位补 0 |
| 3 | `block1` | `64@192×704` | `64@96×352` | ZeroPad+Conv3×3/s2 + 3×(conv+BN+ReLU) |
| 4 | `block2` | `64@96×352` | `128@48×176` | ZeroPad+Conv3×3/s2 + 5 convs |
| 5 | `block3` | `128@48×176` | `256@24×88` | ZeroPad+Conv3×3/s2 + 8 convs |
| 6 | `deblock1/2/3` | 三尺度 | 各 `128@96×352` | ConvTranspose s1/s2/s4 |
| 7 | `concat` | — | **`(N_pil, 384, 96, 352)`** | 通道拼接 |
| 8 | `shrink_conv` | `384@96×352` | **`(N_pil, 256, 48, 176)`** | Conv3×3/s2 + Conv3×3 |

`N_pil` = `Σ record_len` = 9（上例 5+4）。注意这里**不是 B**：每辆车都有一张自己的 BEV 特征图。

## 6. 阶段 4：V2X-ViT 融合（本模型核心）

```python
# point_pillar_transformer.py:99-114
regroup_feature, mask = regroup(spatial_features_2d, record_len, max_cav=5)
#   regroup_feature: (B, 5, 256, 48, 176)
#   mask:            (B, 5)   [1,1,1,1,1] / [1,1,1,1,0]

prior = prior_encoding.unsqueeze(-1).unsqueeze(-1)          # (B,5,3,1,1)
prior = prior.repeat(1,1,1,48,176)                           # (B,5,3,48,176)
x = cat([regroup_feature, prior], dim=2)                     # (B,5,259,48,176)
x = x.permute(0,1,3,4,2)                                     # (B,5,48,176,259)

fused = self.fusion_net(x, mask, spatial_correction_matrix)
fused = fused.permute(0,3,1,2)                               # (B,256,48,176)
```

`V2XTEncoder.forward` 内部：

| 步骤 | 输入 → 输出 | 说明 |
|---|---|---|
| 拆分先验 | `(B,5,48,176,259)` → `x:(B,5,48,176,256)`, `prior:(B,5,48,176,3)` | `x[..., -3:]` |
| RTE | `x + SinEmb(dt)` | `dt` 取自 `prior[...,1]`（时延帧数） |
| STTF | 非 ego 特征被 warp | `discrete_ratio=0.4`、`downsample_rate=4`，与 `48 = 192/4` 对应 |
| com_mask | `(B,1,1,1,5)`（不使用 ROI）或 `(B,48,176,1,5)`（`use_roi_mask: true`） | 最后一维是车辆维，用于屏蔽无效车 |
| Block ×3 | `(B,5,48,176,256)` 不变 | 每块 = HGT 跨车注意力 + 金字塔窗口注意力 + FFN |
| 输出 | `output[:, 0]` → `(B,48,176,256)` | **只取 ego** |

> **48 这个数字不是随便定的**：`PyramidWindowAttention` 依赖 `rearrange('b l (new_h w_h) (new_w w_w) ...')`，要求 H 能被 `window_size` 整除。`48 % 4/8/16 == 0` ✅，而 `50 % 4 != 0` ❌。因此**只要沿用 V2X-ViT 的窗口配置，就不能把范围改回 ±40**（CoBEVT 的 `window_size: 4` 同理）。

## 7. 阶段 5：检测头与损失

```
fused (B,256,48,176)
 ├─ cls_head Conv1×1(256→2)  → psm (B, 2, 48, 176)
 └─ reg_head Conv1×1(256→14) → rm  (B, 14, 48, 176)
```

**参数量**：`cls_head` = 256×2+2 = 514；`reg_head` = 256×14+14 = 3598。检测头极轻，说明**绝大部分参数在 backbone**——这也是「换融合模块只增加少量参数」的原因。

### 损失计算中的形状对齐

```python
# loss/point_pillar_loss.py:95-137
cls_preds = psm.permute(0,2,3,1).contiguous()          # (B,48,176,2)
box_cls_labels = pos_equal_one.view(B, -1)             # (B, 16896)   ← 48*176*2
cls_preds = cls_preds.view(B, -1, 1)                   # (B, 16896, 1)
one_hot_targets = ...                                  # (B, 16896, 1)

rm = rm.permute(0,2,3,1).view(B, -1, 7)                # (B, 16896, 7)
targets = targets.view(B, -1, 7)                       # (B, 16896, 7)
```

> 这里 `psm` 的**空间分辨率**（48×176 = 8448）与 **anchor 数**（16896）不是同一个量——`psm` 的通道维是 anchor 数（2）。`reshape` 把「空间 × anchor」压平后恰好等于 16896。**只要 `feature_stride` 与 `shrink.stride` 一致，这个等式自动成立**；不一致则在此处或 `delta_to_boxes3d` 处报错。

## 8. 阶段 6：训练循环

```python
# tools/train.py:140-179
for epoch in range(init_epoch, epoches):
    for i, batch_data in enumerate(train_loader):
        model.train(); model.zero_grad(); optimizer.zero_grad()
        batch_data = train_utils.to_device(batch_data, device)   # 递归 .to(cuda)
        output_dict = model(batch_data['ego'])                   # ★ 只传 ego 键
        final_loss  = criterion(output_dict, batch_data['ego']['label_dict'])
        final_loss.backward(); optimizer.step()
```

三个值得注意的点：

1. **只有 `batch_data['ego']` 被传入模型**。中间/早期融合把「所有车的数据」都打包在 `ego` 这个键下（`processed_lidar` 内是列表），只有晚期融合才有多个键。
2. **`model.train()` 写在 batch 循环内**——每步都重设，无副作用但冗余。
3. **验证只算 loss，不算 AP**（`train.py:185-201`）。AP 必须跑 `inference.py`。这是 OpenCOOD 的重要工作流特点：**训练用 loss 判收敛，最终指标靠离线推理**。

学习率调度（cosine 分支）：

```python
scheduler.step_update(epoch * num_steps + i)     # 按 iteration
```

## 9. 阶段 7：推理与评估

`tools/inference.py:103-202`：

```
for each sample（batch_size=1）:
    ① collate_batch_test
         · 额外附 anchor_box (48,176,2,7)
         · transformation_matrix = I（中间融合的框已在 ego 系）
    ② inference_intermediate_fusion → 内部直接复用 early fusion 的调用
         output_dict = {'ego': model(batch_data['ego'])}
    ③ dataset.post_process(batch_data, output_dict)
         · sigmoid(psm) → prob (1, 16896)
         · delta_to_boxes3d(rm, anchors) → (1, 16896, 7)
         · 阈值 score_threshold(0.27) 筛选 → 转 8 角点 → 投影 → 2D standup
         · 剔除超大框/异常 z → 旋转 NMS(0.15) → 范围过滤(GT_RANGE)
         → pred_box3d (N, 8, 3), scores (N,)
    ④ caluclate_tp_fp(..., 0.3/0.5/0.7)   ← 累积 TP/FP 到 result_stat
 ↓
 eval_final_results → VOC 2010 AP → 写 <model_dir>/eval.yaml
                      （开 --global_sort_detections 时写 eval_global_sort.yaml）
```

### 9.1 `transformation_matrix` 为什么是 I

中间融合的检测头作用在**ego 视角的融合特征**上，输出的框天生就在 ego 坐标系，因此 `post_process` 里再乘一个 `I` 不改变结果。

晚期融合不同：每辆车在自己的坐标系下推理，必须各自乘 `cav_content['transformation_matrix']` 投到 ego，再统一 NMS——这是 `LateFusionDataset` 与另外两者的关键后处理差异。

### 9.2 `global_sort_detections` 的陷阱

```python
pred_box2d_list = torch.vstack(pred_box2d_list)
scores = pred_box2d_list[:, -1]
# 默认：逐帧累积 TP/FP，等价于「逐帧 AP」
# global_sort=True：把所有帧的检测框放在一起按分数排序，等价于「全局 AP」
```

README 明确指出：**OPV2V 论文用的是非全局排序**。若你的数字比论文高 5~10 个点，很可能是不小心开了 `--global_sort_detections`（它对 FP 更宽容，因为高分框可以跨帧「抢占」排名）。

## 11. 一次前向的显存估算（B=1, L=5，仅前向）

| 张量 | 元素数 | float32 |
|---|---|---|
| `spatial_features` | 5×64×192×704 ≈ 4.3e7 | ~173 MB |
| `spatial_features_2d` (384ch) | 5×384×96×352 ≈ 6.5e7 | ~260 MB |
| `x` 融合输入 | 5×48×176×259 ≈ 1.09e7 | ~44 MB |
| 注意力图（每层，8 头） | 1×8×48×176×5×5 ≈ 1.69e6 | ~7 MB/层 |
| **前向合计** | — | **约 0.5~0.8 GB** |

训练还需保存反向激活，通常再乘 4~8 倍，**单卡约 4~6 GB**。这解释了为什么 V2X-ViT 的 `batch_size` 只有 2（V2VNet 是 4）——L 维注意力与 384 通道高分辨率特征共同抬高了显存门槛。

> 以上为**估算值**，随 L、点数与框架的显存复用策略变化，仅用于量级判断。
